# Elementor maintenance compatibility (1.0.22)

## Cause and implementation

OTP prepares its widget, title and form type in WordPress query variables on
`template_redirect` at `PHP_INT_MIN`. Elementor's maintenance handler later calls
`query_posts()` at priority 11, replacing the query before the OTP card reads it.
This leaves an empty widget and form type while static instructions and Submit
remain visible.

The integration registers `elementor/maintenance_mode/is_login_page` during main
plugin loading. Elementor evaluates this filter before replacing the global post
and query, for both Coming Soon and Maintenance Mode. Reference:
[Elementor Maintenance_Mode::template_redirect](https://github.com/elementor/elementor/blob/main/includes/maintenance-mode.php).

Only the exact paths generated by `home_url('/otpa/passwordless-login')` and
`home_url('/otpa-api/otp')`, with an optional single trailing slash, are exempt.
Query strings are ignored for matching and never modified. Using the home URL
supports sites served from a subdirectory (including when the WordPress core
directory differs from the public home URL). Paths are not decoded or matched by
prefix; children, lookalikes, query-variable aliases and shortcode host pages do
not acquire an exception. Existing true filter results are preserved.

No Elementor classes or Pro APIs are required. If Elementor is disabled, or an
older version never calls this filter, registration is inert. Versions without
the filter do not gain maintenance compatibility; there is deliberately no broad
option override or removal of Elementor's handler. The installed Elementor
version must expose the documented filter. No installed Elementor/Pro version was
available in the lightweight test environment.

## Security and unchanged behavior

This is only a maintenance-template exception. Existing OTP routing, nonce
verification, code checks, throttling, expiration, safe redirects and WordPress
authentication/authorization still execute. No settings, dashboard restrictions,
Hide Login rules, shortcode rendering, CSS, Dashicons, Extra Button or updater
code changes. Other public pages (including pages containing the shortcode)
retain Elementor's normal maintenance policy. Package directory
`clever-otp-authenticator-main` and entry point `clever-otp-authenticator.php`
are unchanged.

## Automated checks

Run `php tests/elementor-maintenance-mode.php`, existing PHP tests
`tests/inactivity.php` and `tests/hide-login-logout.php`, plus
`node tests/inactivity.js`. Lint all first-party PHP files. The new contract test
boots the real entry point with WordPress doubles, verifies early registration,
exact route matching, root/subdirectory homes, query preservation, malformed
requests, existing filter decisions and modeled query replacement for both modes.
It does not claim to test real Elementor rendering, email delivery or login.
CI includes PHP 8.1 and 8.3 alongside the existing 7.0 and 8.4 matrix.

## Live staging checklist (requires WordPress; not covered by contract doubles)

Use a logged-out browser, an email gateway test account and a configured Elementor
maintenance template. Repeat with Elementor Pro active and inactive, on PHP 8.1
and 8.3, and with root and subdirectory home URLs. Clear page caches after mode
changes; any CDN/server maintenance rules must also allow the authentication URLs.

1. Coming Soon ON: open `/otpa/passwordless-login/` and confirm the heading,
   Email input, OTP Code input, Send Code and Submit render. Submit should remain
   disabled until the existing form validation enables it.
2. Repeat with Maintenance Mode ON; the OTP page must retain its form variables.
3. Disable Elementor entirely and repeat passwordless login and the shortcode.
4. Request an email code through `/otpa-api/otp`; verify valid nonce handling,
   request throttling and expiration. Missing/invalid nonces must still fail.
5. Submit an invalid OTP and confirm rejection without an authentication cookie;
   request a fresh code and complete a successful login.
6. Start with `?redirect_to=` pointing to a permitted internal destination; confirm
   the successful login preserves that destination. Check the configured default
   redirect when omitted and confirm external redirect validation still applies.
7. Visit unrelated pages, a shortcode host page, endpoint children and lookalikes
   as a logged-out user: Elementor's template must remain effective (Coming Soon
   normally 200, Maintenance normally 503). Neither query aliases nor a
   `redirect_to` value containing an OTP path may exempt another page.
8. Disable maintenance and confirm `[otpa_passwordless_login]` still renders and
   authenticates normally, including its redirect and logo attributes.
9. With Hide Login enabled, verify its public slug and blocked default login/admin
   requests behave as before. Verify native nonce-protected logout, administrator
   and super-admin dashboard access, restricted-role dashboard and admin bar rules.
10. Confirm Extra Button, form styling/Dashicons and updater settings are intact.

No PR merge or GitHub Release is part of this change.
